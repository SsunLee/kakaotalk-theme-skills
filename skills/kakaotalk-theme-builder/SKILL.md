# 카카오톡 테마 제작

사용자가 소유하거나 사용을 허락받은 원화와 네이티브 테마 프로젝트로 설치 파일, 미리보기, 설치 안내, 배포 ZIP을 만든다. 기존 파일을 우선 확인하고 재사용한다. 테마 제작 요청에 판매 사이트 게시 권한을 추가로 추정하지 않는다.

## 작업에 맞는 문서

- 처음 제작하거나 기존 원화를 구현할 때: [제작 절차](references/creation.md).
- 말풍선, 캐릭터, 색상, 미리보기를 설계·수정할 때: [디자인과 검수](references/design-review.md).
- 프로젝트 초기화, 패키징, Android 빌드: [도구 사용법과 파일 규격](references/tooling.md).

## 수행 순서

1. 작업 폴더의 설정, 원화, 설치 파일, 검증 기록을 확인한다. 운영체제, 제작자명, 고유 패키지 ID와 현재 디자인 선택을 유지한다. 부족한 선택 중 구현에 영향을 주는 항목만 확인한다.
2. 기존 원화가 없으면 사용 가능한 이미지 생성 도구나 사용자 제공 에셋으로 제작한다. 도구 이용료·접근 권한은 해당 환경에 따른다. 생성 도구가 없는 상태를 생성 완료로 표시하지 않는다.
3. 현재 카카오 공식 테마 안내와 사용자 프로젝트를 기준으로 리소스를 만든다. 공식 예제·타사 이미지를 저장소나 상품에 허가 없이 포함하지 않는다. 이 스킬에는 완성 캐릭터나 공식 예제 소스가 포함되지 않는다.
4. iOS CSS와 이미지, Android manifest·Java·리소스를 구현한다. 공식 예제의 필수 파일명과 리소스 키를 보존한다. 서명키는 사용자의 키를 사용하며 저장소에 넣지 않는다.
5. 설치 리소스와 일치하는 미리보기 7장을 준비한다. 전체, 암호 화면, 설치 안내, 탭 아이콘, 말풍선, 채팅, 친구목록을 기본 구성으로 삼되 사용자가 정한 구성을 우선한다.
6. 구조·파일 검사를 실행하고 이미지와 실제 적용 검증을 구분한다. 서명 성공은 카카오톡 적용 성공을 뜻하지 않는다. 실제 검사하지 않은 항목을 검증 완료로 기록하지 않는다.
7. 설치 안내와 사용 범위를 작성한 뒤 배포 ZIP과 SHA-256 목록을 만든다. 기존 보관함 연결 요청이 있으면 지정 사이트와 공개 범위를 유지해 연결한다. 특정 계정·사이트는 이 스킬의 기본 대상이 아니다.

## 제공 도구

Python 3.10 이상에서 실행한다. 모든 경로는 이 SKILL.md가 있는 폴더를 기준으로 해석한다.

```text
python scripts/theme_tools.py init --project <작업폴더> --slug <영문이름> --name <테마명> --package <고유패키지ID>
python scripts/theme_tools.py pack-ios --project <작업폴더>
python scripts/theme_tools.py check --project <작업폴더>
python scripts/theme_tools.py package --project <작업폴더>
python scripts/build_android.py --help
```

`init`은 빈 작업 틀만 만든다. 원화·CSS·Android 소스·미리보기는 에이전트가 사용자 요청과 최신 네이티브 규격에 맞춰 구현해야 한다. Android 빌더는 외부 Java 라이브러리나 Kotlin을 쓰지 않는 단순 Java 프로젝트용이다. 다른 프로젝트는 해당 프로젝트의 빌드 절차를 사용하고 결과물을 같은 파일 규격에 맞춘다.

## 실행과 보고

외부 터미널을 열거나 입력 초점을 가져오지 않는다. Windows 자식 프로세스는 직접 실행, 비대화형 입력, 창 숨김 옵션을 사용한다. 도구 자체가 창을 띄우면 그 경로를 중단하고 한계를 알린다. 창 숨김 옵션만으로 실제 화면 보호를 검증했다고 말하지 않는다.

완료 보고에는 설치 파일·미리보기·ZIP의 위치, 수행한 검사, 실제 기기 적용 여부를 적는다. 업로드 요청도 있으면 별도로 설치된 `kakaotalk-theme-publisher`를 사용하거나 사용자의 플랫폼 등록 절차를 따른다. 제작 스킬만 설치되어 있어도 제작·검수·패키징은 가능하다.
